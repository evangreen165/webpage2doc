# Решения (ADR)

Журнал архитектурных решений. Формат: ID, решение, почему, последствия. Изменение решения оформляется новым ADR, старый помечается как заменённый.

| ID | Решение | Почему | Последствия |
|---|---|---|---|
| ADR-001 | MV3 + Side Panel (не popup/страница) | рендер и zip тяжёлые, нужна живая страница с полноценным DOM | нужен Chrome ≥ 114 |
| ADR-002 | Vite multi-entry + esbuild для content/SW, без vite-plugin-web-extension | минимум зависимостей и рисков сборки | ручная пересборка при разработке (build --watch) |
| ADR-003 | Картинки качаются в контексте панели, не в content script | fetch из content script подчинён CORS страницы; `host_permissions` обходит его | широкое разрешение «все сайты» (принято) |
| ADR-004 | Единая модель Snapshot между сбором и рендерами | форматы не зависят от извлечения | +1 слой типов |
| ADR-005 | PDF — html2pdf.js (html2canvas+jsPDF) поверх чистого документа | чистота вывода и контроль памяти; кириллица из системных шрифтов | лимит ~50 страниц, warning |
| ADR-006 | MD — turndown+gfm, DOCX — docx | стандартные библиотеки, MPL/MIT совместимы | поддержка подмножества Markdown |
| ADR-007 | Извлечение — @mozilla/readability + fallback | вычищенный HTML без своего экстрактора | MPL-2.0 (файловая), возможна потеря контента → warning |
| ADR-008 | История в localStorage панели, max 10 | как и раньше (w2d.history.v1) | история не переживает очистку данных браузера |
| ADR-009 | ZIP — jszip + chrome.downloads.download(blob:) | один файл с документом и images/ | saveAs: true, имя-слаг |
| ADR-010 | Без бэкенда: FastAPI/PyInstaller отменены | локальный процесс в браузере, нет SSRF/сетевых рисков | зависимости ограничены browser env |
